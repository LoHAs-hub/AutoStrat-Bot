# A2 最小原生驗證步驟（尚未執行）

用途：取得第一份可審閱的原生行為／微台績效證據，不做參數搜尋。需要可用且已有權使用的 TradingView 登入研究介面；目前匿名編輯器 Ctrl+Enter 只得到登入畫面。這是能力缺口，不是等待使用者選策略參數。

1. 在 TradingView 開啟 **TAIFEX:TMF1!**、標準 K 線，起點 **30 分鐘**。保存商品身分、圖表時區、日夜盤、延遲標記、B-ADJ／SET 狀態與實際可用歷史起訖。若某設定無法核實，先標不明及其影響，不能稱已清除換月偏差。不得用 TXF 或小台替代。
2. 將 [tmf002_a2.pine](tmf002_a2.pine) 放入原生 Pine Editor，編譯並加入圖表；**原型未經原生編譯，可能需要修正**。若出錯，保留完整錯誤文字、行號與版本。若成功，保留設定與圖上訊號；成功編譯不是策略驗證。無需 Publish、Broker、alert 或 webhook。
3. 核對 Properties：圖表貨幣 TWD、一口、pyramiding 0、現金費用每口每邊 29.8、滑價 3 tick、限價穿透 1 tick、初始研究資本 1,000,000、名義保證金 100%、收盤即成交關閉、每 tick 重算關閉、成交後重算開啟、Bar Magnifier 關閉。介面如覆蓋了程式預設需記錄。帳號功能限制不能直接用付費功能補上。
4. 先用預設 Retest 檢視少量有辨識力的案例：正常確認、最後等待根、取消／逾時、停損、跳空失效、盤末與午夜。橘圓是突破事件，三角形是**訊號確認**，TradingView 交易標記是**模擬成交**。水平橘／紅線是凍結 B/S；綠線只在已觀察模擬成交後依 E 計算。逐筆核對委託形成在確認後、最早下一 tick 成交，不把三角位置當成交價。
5. 查看 Data Window 診斷：Episode count、突破事件 Unix 時間與方向、confirmed signals、invalid/gap fills、same-session gaps、unexpected cross-session exposure、expected entries not observed。非零異常先追到日期與成交；ROD 是否有效不能由 Pine 持續存在的模擬保護單證明。重載後比對已完成根訊號；即時重載未觀察到足夠案例時如實標未驗證。
6. 在相同圖表／期間／參數／成本下切換 Direct。先核對兩邊**事件時間與數量**，再看交易。若不同，先修正資金、資料缺口或成交重算等問題，不能直接宣稱其中策略較優。Pine 原型提供事件辨識，但尚未自動產出成對事件損益表；原生核對／整理工作仍未完成。
7. 功能可信後，以可用的開發歷史執行兩模式，保留原生設定、日期、逐筆表及報表。每事件淨結果需包含 Retest 未進場的零結果，區分正常未進場與資金／委託異常；另報多空交易數、每筆／每事件淨損益、尾部損失、回撤、曝險及漏失趨勢。回撤依時間序列解讀，不能拿少量案例外推個人資金能力。
8. 再做少量事先記錄的成本壓力情境，沿用佣金每邊 10／20／30、滑價 1／3／5 tick 作粗略而未校準假設；報稅額固定近似的影響，不能將其當成實際費率範圍。同根觸及 S/T 的交易列路徑歧義，無細資料時報可能差異，不挑有利路徑。歷史不足、Bar Magnifier 不可用或換月未知時，指出哪個結論因此不能成立，不擴展為供應商調查。

第一份回傳只需讓 Agent 讀到：商品與圖表設定、編譯結果（成功或錯誤均可）、兩模式的事件診斷和原生交易報表／代表案例。若要從平台外自動處理行情另確認使用權；可讀報表審閱不等於授權批次行情運算。

不要為漂亮結果重跑參數後稱樣本外。先保存開發結果與全部修改；只有未參與觀察／調整的獨立資料才能另作留出。若資料量不足以區分假說，結論就是不足；若等待版本較差也照實保留。Agent 在既有研究授權內接續選擇合適方法，不另要求日常設定批准。
